# 多前端北极星（规划，不代表已上线）

## 目标

同一份作者内容可以由不同的静态前端展示，但每个前端仍是独立产品、独立代码和独立发布物。
eDEX Web 保持高保真终端体验；未来的极简前端提供直接、轻量的文章与媒体浏览。
访客可以从一个清楚的入口选择体验，不需要理解内容后台或数据库。

## 默认规划边界

| 部分 | 责任与代码位置 | 不负责什么 |
| --- | --- | --- |
| eDEX Web | 本仓库的 `apps/clone`、视觉基准、交互与当前 `deploy:site` | 不承载极简前端或通用站点首页 |
| 极简前端 | 独立的 `SekerMinimalWeb` 仓库；当前是视觉样稿，尚未接入 API | 不复制 eDEX UI、素材、构建脚本或数据库 |
| 内容服务 | 独立的 `SekerContentApi` 仓库；独立运行、持有 SQLite 和媒体 | 不决定任何前端的布局、路由或发布节奏 |
| 多入口首页 | 未来独立的轻量入口页/站点，只提供明确的前端链接 | 不嵌在 eDEX 画布中，不读私有数据，不代替内容后台 |

内容服务源码已作为专门的迁移任务从 eDEX 仓库拆出，`/api/v1` HTTP 契约保持不变。
两个前端不导入后端源码；后端构建、CI 与发布由 `SekerContentApi` 自己维护。

## 数据与文件如何分开

- 一份内容事实源：作者文章、链接、目录、顺序、图片和视频只保存在服务私有数据库/媒体卷。
  各前端通过同一版本化只读 API 获取已发布数据；浏览器不连 SQLite，前端仓库不放真实内容。
- 各前端自行决定页面路由和样式，但不重新定义作者内容的身份或排序。内容的 `relativePath`
  是服务内容树中的路径，不是某个前端仓库或 OSS 对象路径。媒体 URL 由 API 提供，不复制一份到各站点。
- 代码目录和部署对象同样隔离：极简前端不放进 `apps/clone`，也不把产物上传到当前 eDEX
  发布脚本拥有的 Bucket 根目录、`assets/`、`index.html` 或 `deployment.json`。未来每个站点要有
  独立的静态发布目标及对象所有权清单；入口页也不与 eDEX 共用同一发布入口。
- 公共 API 对每个前端的 HTTPS origin 单独配置 CORS；不使用通配符，也不把管理员凭据交给前端。
  API 不可用时每个前端明确显示内容不可用，不回退示例或静默展示陈旧的另一套内容。

## 访客入口

目标形态是一个中性首页提供“eDEX Web”和“极简阅读”两个入口，两个入口各自保留可直达的地址。
**这不是要把当前 eDEX 首页改成选择页。** 当前生产根地址、静态对象和 eDEX 视觉合同保持原状；
入口页的正式域名、各前端地址及迁移/回滚方案须在单独的上线决策中确定。未确定前，可先用
各站点之间的普通链接验证导航，但不得破坏 eDEX 的固定参考场景。

## V1 成功条件与非目标

未来第一个多前端闭环：极简前端在自己的仓库和测试地址独立构建；它与 eDEX 同时从测试内容
API 读取同一条已发布文章和媒体，草稿均不可见；修改内容无需重建任一前端；发布一个前端
不会覆盖另一个前端的文件。只有这些证据成立，才考虑入口页和生产地址切换。

独立极简前端仓库和内容服务拆仓已完成，但这**不**授权修改当前首页、迁移旧数据或发布生产；
也不引入账号系统、通用组件库、共享前端包或第二份内容数据库。当前状态与仓库可见性见
[三仓库项目地图](REPOSITORY_MAP.md)，后续执行顺序与门禁见
[多前端任务合同](multi-frontend-task-contract.md)。
