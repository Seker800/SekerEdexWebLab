# ADR 0008: 记录已验证的浏览器实现路线

- Status: Accepted
- Date: 2026-10-18
- Supersedes: ADR 0003 的具体框架、包管理器和渲染库选择；保留其类型边界、浏览器沙箱和验证原则
- Clarifies: ADR 0001 的素材选择建议；许可证、文件级来源和非官方身份要求继续有效

## Context

早期 ADR 0003 与技术路线仍描述 Astro、React、xterm.js、直接 Three.js、Canvas 图表和 pnpm。
当前源码、npm lockfile 与可执行门禁实际上采用 Vite、原生 DOM、SVG 图表、原版 ENCOM、
Web Audio WAV 播放及框架无关控制器。继续把旧设想标为唯一现行路线，会让维护者误判依赖缺失，
甚至为追赶文档进行没有证据支持的框架重写。

这次不改变框架。2026-10-18 的修改前完整门禁通过；正式截图差异约 2.18%，感知差异约 4.65%，
分别低于现行 3.5% 与 6% 预算。历史回归语料也记录了恢复旧 xterm Canvas 导致更差的区域结果。
这些证据支持记录现状，不支持声称当前技术路线已在所有未来规模上最优。

## Decision

- 以 `package.json`、`package-lock.json`、`apps/clone` 和 [技术路线](../technical-route.md)
  共同描述现行工具链；旧 ADR 保留原文并明确指向本决策。
- 保留已经验证的 DOM 终端、SVG 图表、ENCOM 与 WAV 适配器；不为满足过时文字重新引入框架。
- 持续动画仍由统一调度器管理，内容、会话、渲染和音频通过窄接口协作。
- 上游素材继续按现有文件级来源和哈希门禁管理；本 ADR 不增加素材授权或更改许可证。
- 固定画布、场景阈值、证据与判定器保持原合同。未来换栈必须单独提供测量、迁移方案和 ADR。

## Consequences

文档现在能指导真实的安装、维护和验证。入口组装文件较大仍是可继续改善的维护成本；
应在实际功能修改时按责任拆分，避免把状态迁入 DOM 或为抽象而建立通用框架。
API 大规模内容仍需要同步终端读取协议与内容仓库一起演进，不能只对阅读器做惰性加载。
