# ADR 0005：网站与作者内容使用独立发布线

## 状态

已接受。

## 背景

作者内容已经存放在公开程序仓库之外，但早期生产脚本仍在网站构建时读取 Markdown 和图片，把程序提交与
内容摘要打进同一个静态产物。这样修改一篇文章也必须重建整站，网站清理过程还拥有内容对象，两个版本
无法独立回滚，Agent 也容易把“更新博客”误解成“重新部署网站”。

## 决策

建立两个互斥的生产入口：

- `npm run deploy:site` 只发布 Git `main` 的网站程序。生产构建使用运行时内容模式，不读取作者内容根；
  它拥有除 `content/` 以外的对象，并用根目录 `deployment.json` 记录程序提交。
- `npm run publish:content` 只读取外部 `author` 内容根。它拥有 `content/`，创建基于内容摘要的不可变
  release，最后原子更新 `content/current.json`；它不构建或上传网站。

浏览器通过 `content/current.json` 和版本化清单异步读取作者内容。指针或清单失败时保持空作者内容状态，
不回退公开示例。旧 release 保留，两个发布线可以独立上线和回滚。

`npm run release:verify` 对脚本入口、对象所有权和文档双向引用执行机器门禁；含糊的 `npm run deploy`
被删除。

## 后果

- 文章和图片可以高频发布，不依赖程序提交或整站构建。
- 网站发布不接触私人内容源，也不能删除内容版本。
- 网站版本与内容版本分别通过 Git revision 和内容 digest 追踪。
- 运行时首次进入需要额外读取小型指针与清单；媒体仍使用不可变缓存。
- 引入新内容能力仍属于网站代码变更，必须先走网站发布线，再独立发布使用该能力的内容。
