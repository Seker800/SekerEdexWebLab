# ADR 0006：独立内容数据库、后台与多前端只读 API

- Status: Accepted for local implementation; production rollout requires separate approval
- Date: 2026-10-11
- Supersedes: ADR 0005 的静态作者内容发布路线

## 背景

作者不需要复杂编辑器，只要粘贴 Markdown、保存文章链接，并对图片/视频管理目录和顺序。内容更新应与阿里云静态网站代码发布完全分离；同一份内容还应被其他静态前端读取。旧样例不迁移，公开 Git 仓库不应承载真实内容或凭据。

## 决策

- 保留当前 Vite 静态前端与 `npm run deploy:site` 网站发布方式；生产包只包含公开 API origin，运行时从独立内容服务 GET 已发布清单和媒体。公开示例只用于本地开发/CI，失败不回退。
- 新增 Node 22 内容服务。SQLite 单文件数据库保存 Markdown、HTTPS 链接、媒体元数据、层级路径、顺序与 `draft/published` 状态；媒体字节在同一私有数据卷。无需为低流量个人站引入常驻 PostgreSQL。
- 后台用独立私有 HTTPS 入口管理内容，要求管理员密码哈希、Basic Auth、写请求 Origin 校验、输入验证、上传大小/类型/文件头限制。公开反向代理只允许只读 API；SQLite 不开放网络端口。静态前端读取允许 origin 列表，不携带管理员凭据。
- 数据库及媒体、备份、密码哈希、私有配置留在运行环境，不进公开 GitHub、CI 或阿里云静态产物。程序、数据库 schema、测试、部署模板及标为 `sample` 的示例可以开源。
- 内容数据发布就是后台状态切换，不再执行 `publish:content` 或修改旧 OSS `content/`。内容服务代码升级与静态网站发布是独立的代码操作；本次不执行生产部署。

## 后果与边界

- 多个静态前端可使用同一 API，但每个 origin 需显式列入 CORS；浏览器永不直接连接数据库。
- 内容服务和家庭网络成为公开内容的可用性依赖；生产前必须准备可靠 HTTPS 入口、外网实测、备份恢复、最小权限与监控。家宽 80/443 入站限制不能靠代码消除。
- SQLite 单写入者适合低并发管理；若未来出现多写入者或较大流量，先测量，再评估迁移到 PostgreSQL。前端只依赖版本化 API，不依赖数据库品牌。
- 旧 OSS 内容对象保留，网站发布不得删除；它们不再是新内容事实源。没有自动数据迁移。
