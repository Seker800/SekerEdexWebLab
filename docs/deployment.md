# 代码与内容的独立工作流

当前目标是：阿里云只托管静态前端；独立内容服务持有 SQLite 数据库、上传媒体和管理后台。任意数量的静态前端可通过 HTTPS 读取同一内容 API，浏览器不能直接连接数据库。多前端的产品、仓库和部署隔离见[北极星](MULTI_FRONTEND_NORTH_STAR.md)；现有 `deploy:site` 仅归 eDEX Web，不自动拥有未来极简前端或入口页。本文是发布决策门禁；2026-10-18 作者已授权 ADR 0009 中的双前端静态站落地，不含内容服务或数据迁移。

先判断本次任务：只想看效果或跑测试，走 [本地测试与预览](local-testing.md)，到此停止；
要改网站程序，走 [网站程序发布](site-deployment.md)；要修改作者内容，走
[后台内容管理](content-publishing.md)。内容服务程序升级是第四条独立代码线，当前没有
获批的生产执行入口。**本地测试通过不会自动授权 Git push、网站发布、服务部署或数据迁移。**

| 变更 | 数据所在位置 | 操作入口 | 是否修改公开 Git 仓库 | 是否重建阿里云前端 |
| --- | --- | --- | --- | --- |
| eDEX 前端代码、样式、内容展示协议、示例 | 本公开仓库 | 测试后单独执行 `npm run deploy:site` | 是 | 是 |
| 内容服务代码、数据库结构、后台功能 | 独立 `SekerContentApi` 仓库；运行数据在私有卷 | 在服务仓库运行 `npm run verify`；生产升级需另行审查与授权 | 修改服务仓库 | 通常否；协议不兼容时分两次上线 |
| 作者文章、链接、图片、视频、目录和顺序 | 私有数据库及媒体卷 | 上线后在已部署的私有后台编辑和发布；本机测试才在服务仓库运行 `npm run serve` | 否 | 否 |

本仓库不提供内容数据上传脚本，旧的静态 `publish:content` 入口已撤销。不得把数据库文件、媒体原件、草稿、备份、密码哈希、`.env`、令牌或个人内容复制进本仓库、GitHub Actions 或阿里云静态构建。仓库可以包含数据库结构、程序、测试、空示例配置和明确标为 `sample` 的演示材料；即使作者已把文章公开，也不意味着其编辑历史应进入开源 Git。

## 生产边界

- `npm run deploy:site` 只发布网站程序，见 [网站程序发布](site-deployment.md)。它不读取内容数据库，也不写入旧的 `content/` OSS 命名空间。站点的 `site.config.json` 显式选择 sample 或 api；api 模式的 `contentApiOrigin` 是公开 HTTPS 接口地址，不是凭据。
- `SekerContentApi` 中的 `npm run serve` 只在开发机启动内容服务，不是生产发布命令，见 [本地测试与预览](local-testing.md)。生产服务代码升级与数据库迁移必须作为单独变更审查；不得借网站发布顺便重启或替换内容服务。
- 作者改内容只在后台保存草稿或切换发布状态，不改程序提交。公开接口只返回 `published`；读取失败不显示示例文章。
- 网站与 API 使用不同版本和故障域。前端新能力若依赖 API 变更，先验证兼容协议，再分别安排服务与网站上线；不存在一键联合发布。
- 旧 `content/` 对象仍受网站清理保护，本轮不迁移、不删除线上对象。切换生产前必须确认 HTTPS、外网可达性、CORS、管理入口隔离、备份和回滚方案。

`npm run release:verify` 是本地结构门禁：拒绝含糊发布命令、旧内容上传入口和跨越代码/数据边界的实现；它不执行发布。生产发布仍需先检查 `git status --short`，通过规定的测试、DCO 提交、普通 push 和 CI；本轮只执行作者授权的静态站动作，不包含内容服务部署。
