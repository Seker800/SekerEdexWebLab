# eDEX-UI 视觉与交互复刻合同

这份文档定义“能否复刻”的判定方式。它比较的是运行体验，不要求像素级复制品牌资产。

## 参考基线

- 上游：`GitSquared/edex-ui`
- 参考版本：`v2.2.8`
- 参考主题：默认 `tron`
- 目标视口：1920×1080 与 1440×900
- 目标环境：当前稳定版 Chromium 与 WebKit 系浏览器

## 必选体验

### 画面组成

- [ ] 页面进入后形成固定全屏控制台，不出现传统网页首屏加长列表。
- [ ] 中央主舞台承担终端和内容查看器，视觉权重大于辅助面板。
- [ ] 左右至少各有一组持续活动的遥测或日志模块。
- [ ] 底部屏幕键盘具有足够面积，成为设备感的一部分。
- [ ] 边框、切角、刻度、网格和留白共同形成统一的设备语言。

### 运行感

- [ ] 启动序列展示模块自检与分阶段进入，不只是进度条遮罩。
- [ ] 时钟、图表、光标、日志与状态指示器以不同节奏持续活动。
- [ ] 页面隐藏时持续动画和采样暂停，恢复后状态连续。
- [ ] 不操作时仍能感知系统运行，但不会出现无意义的高频闪烁。

### 输入联动

- [ ] 实体键盘按下与屏幕键帽高亮同步。
- [ ] 屏幕键盘可以向终端输入字符和控制键。
- [ ] 点击文件会产生与终端命令等价的导航行为。
- [ ] 操作具有一致的视觉反馈和可关闭的程序化音效。
- [ ] 错误、拒绝、成功和扫描至少具有四种可辨识反馈。

### 内容替换

- [ ] `help`、`ls`、`cd`、`open`、`clear` 和 `theme` 形成最小命令闭环。
- [ ] 可以在主舞台阅读一篇完整文章并返回终端状态。
- [ ] 可以浏览一组摄影作品且不会跳出控制台体验。
- [ ] 可以打开一个设计案例并展示图像与说明。
- [ ] 鼠标路径与命令路径指向同一内容对象。

### 可用性与性能

- [ ] 核心导航支持键盘，并具有可见焦点。
- [ ] `prefers-reduced-motion` 下仍能理解状态变化。
- [ ] 音频默认静音，解锁后可以再次静音。
- [ ] 桌面目标视口在验证设备上交互阶段保持稳定帧率；测量方法和数字写入报告。
- [ ] 移动端提供专门的终端/内容模式，不把桌面三栏和完整键盘等比缩小。

## 明确不算完成

- 只有一张与 eDEX-UI 相似的静态页面。
- CPU、内存、文件树和日志都是无法产生行为的装饰。
- 点击导航后进入普通长页面，控制台只是首页皮肤。
- 只支持命令输入，鼠标用户无法完成主要路径。
- 为了效果强制播放声音、捕获键盘或忽略减少动态效果设置。
- 用录屏代替可操作原型。

## 证据要求

每个 Slice 保存：

1. 目标视口截图或短录屏。
2. 可执行的验证命令和结果。
3. 已知偏差及其原因。
4. 性能采样环境与数据。
5. 是否继续、调整或终止该方向的结论。
