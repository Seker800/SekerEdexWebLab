# Blog V1 产品规范

## 1. Goal

把已经完成的 eDEX-UI 高保真浏览器复刻转化为一个可长期维护、可索引、可阅读的个人技术博客；指挥舱负责建立辨识度，文章内容负责持续价值。

## 2. Product Definition

### 2.1 In-scope

- 首页保留 `tron` 指挥舱视觉语言，并提供清晰的文章、项目、关于和搜索入口。
- 文章列表、文章详情、标签、归档、项目和关于页面使用语义化静态 HTML。
- Markdown/MDX 内容、代码高亮、目录、上一篇/下一篇、RSS、站点地图和基础 SEO。
- 终端输入作为博客导航和搜索的辅助入口，支持 `help`、`home`、`posts`、`search`、`open`、`tags`、`projects`、`about` 和 `clear`。
- 文件系统面板映射文章、标签和项目内容，与普通链接共享同一套路由事实。
- 遥测只展示真实站点或浏览器会话数据，例如文章数量、当前阅读进度、会话时长、在线状态和构建时间。
- 声音、启动动画和动态效果保留为可选体验，偏好可持久化且不阻塞内容访问。

### 2.2 Out-of-scope

- 真实 PTY、远程 shell、任意系统命令、`curses` 应用和终端鼠标协议。
- 访客设备的 CPU 温度、进程表、内存、磁盘和活动网络连接监控。
- 本地磁盘浏览、文件编辑、文件监听和块设备视图。
- 多终端进程、终端进程标题、密码模式和开发者工具快捷键。
- 多键盘布局、完整桌面屏幕键盘、主题市场和任意 CSS 注入。
- 内建 PDF、图片、音视频播放器；文章使用浏览器原生内容能力。
- V1 账号、评论、后台 CMS、服务端搜索和个性化推荐。

### 2.3 Core User Value

访问者可以快速发现、阅读、搜索和分享文章，同时获得具有 eDEX 辨识度的入口体验。视觉效果不能延迟正文、破坏 SEO，或让移动端阅读变得困难。

## 3. Scope Boundaries

### 3.1 Must Have (V1)

1. 首页、文章列表、文章详情、标签、项目、关于和 404 页面。
2. 内容集合 schema、示例文章、草稿过滤、发布日期和更新时间。
3. RSS、站点地图、canonical、Open Graph 和结构化元数据。
4. 站内静态搜索，以及与终端 `search` 命令共享的索引。
5. 桌面、平板和移动端可读布局，完整键盘操作和 reduced motion。
6. 指挥舱入口可跳过，偏好在本地持久化；任何内容都有普通链接入口。

### 3.2 Success Conditions

- 禁用 JavaScript 后仍能打开、阅读和导航文章。
- 文章 URL 可直接访问、刷新和被搜索引擎索引。
- Lighthouse 的 Performance、Accessibility、Best Practices 和 SEO 在生产构建中均达到 90 以上。
- 首页视觉仍可辨认为现有 `tron` 产品，但文章阅读区不受固定 1920×1080 画布约束。
- 终端、文件面板、普通导航和搜索结果都解析到同一内容清单和路由。

### 3.3 Explicit Non-goals

- 不继续追求完整 eDEX 桌面功能等价。
- 不把文章正文塞进终端字符网格。
- 不用模拟系统数据冒充访客设备真实信息。
- 不为保留复刻结构而牺牲内容可发现性和阅读体验。

## 4. Locked Decisions

### 4.1 Product Decisions

- eDEX 复刻是首页体验与视觉来源，博客内容是产品主体。
- `apps/clone` 继续作为冻结参考实现和视觉回归基线，不在原地拆成博客。
- 博客建立独立应用边界，共享经过来源核查的视觉 token、图标和交互思想。
- 屏幕键盘、网络地球和密集遥测只在入口体验中出现，不常驻文章页面。

### 4.2 Technical Decisions

- 博客采用 Astro 静态输出和内容集合；交互只在需要的位置水合。
- Markdown/MDX 文件是 V1 内容源，Git 是发布工作流。
- 搜索索引在构建期生成，V1 不引入数据库或搜索服务。
- 内容路由与导航模型属于博客 domain，终端只发送类型化导航和查询 intent。
- 现有复刻门禁继续只约束 `apps/clone`；博客建立独立的内容、无障碍、响应式和视觉门禁。

## 5. Constraints

- 保留上游 GPLv3 来源、NOTICE 和复制素材哈希边界。
- 不修改冻结参考图、比较阈值或 `apps/clone` 的历史验收语义来适配博客。
- 初始内容不足时使用明确标记的示例文章，不虚构作者经历、项目成果或联系方式。

## 6. Assumptions

- V1 是个人技术博客，主要内容为中文，允许文章提供英文版本。
- 部署目标支持纯静态站点。
- 评论、订阅邮件和访问分析在真实需求出现后单独决策。

## 7. Architecture Notes

```text
Markdown/MDX content
        ↓ build
Content registry ──→ routes / RSS / sitemap / search index
        ↓
navigation intents ← header / command palette / deck filesystem
        ↓
Astro pages + small interactive islands
```

- 首页可加载指挥舱岛；文章页面默认不加载地球、屏幕键盘或连续遥测动画。
- `BlogRepository` 提供文章、标签、项目和搜索的只读查询接口。
- `NavigationController` 解析普通链接和终端命令，输出标准站内 URL。
- 用户偏好只包含声音、动态效果、是否跳过入口和阅读密度。

## 8. Risks

- 指挥舱首屏可能拖慢首次内容呈现；必须设置静态内容入口和性能预算。
- 复刻 CSS 与博客样式可能互相污染；两个应用必须有独立样式入口。
- 视觉趣味可能压过文章可读性；文章模板以正文排版指标验收。

## 9. Acceptance Criteria

- [ ] V1 所有内容路由可直接访问，并在无 JavaScript 时正常阅读。
- [ ] 首页提供文章、项目、关于和搜索的可见普通链接。
- [ ] 终端和文件面板复用同一内容索引，没有第二套路由事实。
- [ ] V1 非目标没有进入依赖或实现计划。
- [ ] 复刻应用的既有验证门禁保持通过。
- [ ] 不存在阻塞实现的核心歧义。
